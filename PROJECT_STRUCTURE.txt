1. НАЗНАЧЕНИЕ И СТЕК
--------------------
Telegram-бот для продавцов FPV-дронов и комплектующих. Умения:
  • 💰 Калькулятор маржи — FSM-расчёт по прайсу, скидки/объёмы, история расчётов;
  • Каталог АКБ — ряды 6S/8S, карточки моделей с фото (вход: «📊 ТТХ»-цепочка
    и раздел «Каталог моделей» в «📚 Шпаргалках»);
  • 🧠 Подбор — экспресс-подбор АКБ (дрон → разъём → ёмкость);
  • 🔎 Поиск — мульти-фильтр по каталогу;
  • 🔧 Своя сборка — FSM «конфигурация → разъём»;
  • 🎯 Сценарии продаж, 💬 Возражения, ❓ FAQ (категории + поиск), стоп-лист,
    памятка, /checklist;
  • ⏰ Напоминания (follow-up) — CRUD личных дел, утренняя сводка в 9:00,
    предварительные напоминания «за 10/5/2 минуты»;
  • 🤖 AI-ассистент — fallback на любой текст, голосовые (распознавание),
    оценка ответов 👍/👎, обратная связь админу.

Стек: Python 3.14 · aiogram 3.13 (FSM в MemoryStorage) · SQLAlchemy 2 async +
aiosqlite (SQLite data/bot.db; переход на PostgreSQL = DB_URL в .env) ·
python-dotenv · aiohttp. AI: Cloudflare AI Worker или YandexGPT+SpeechKit —
выбор через AI_PROVIDER в .env. fpv-ai-proxy — отдельный Node-проект
(Cloudflare Worker) для проксирования AI и раздачи фото моделей.

Запуск:  .venv\Scripts\python.exe bot.py   (из корня; в .env нужен BOT_TOKEN)
Тесты:   .venv\Scripts\python.exe -m pytest -q   → 154 passed
Проверки: .venv\Scripts\python.exe -X utf8 _verify_<имя>.py

3. СЛОИ И НАПРАВЛЕНИЕ ЗАВИСИМОСТЕЙ
----------------------------------
config ← data/states/keyboards/utils/ai/services ← handlers ← bot.py

Зависимости строго в одну сторону, циклов нет:
  • каждый модуль берёт общие ресурсы (bot, логгеры, env) только из config;
  • каждый роутер объявляет свой Router и НЕ импортирует bot.py;
  • хендлеры переиспользуют show-функции и тексты друг друга (например,
    cheatsheets рендерит экраны через функции scenarios/faq/objections/selection).

4. ТОЧКА ВХОДА bot.py — ПОРЯДОК РОУТЕРОВ И ЗАПУСК
-------------------------------------------------
Порядок include_router КРИТИЧЕН (aiogram отдаёт апдейт первому подходящему):
  0) early_buttons — «ранние» кнопки «🤖 AI-ассистент» и «📚 Шпаргалки»:
     открываются из любого FSM-сценария (нажатие сбрасывает сценарий и открывает
     раздел; раньше кнопку «съедал» активный сценарий — «выход в меню»);
  1) calculator — FSM-ввод не должен перехватываться fallback'ом AI;
  2) menu — /start, callback model:<код> из сценариев обрабатывается здесь;
  3) cheatsheets — «📚 Шпаргалки» (cheat:*) сразу после menu;
  4) scenarios — после menu: кнопки «📦 Карточка <модель>» перехватывает menu;
  5) followup — FSM ограничен FollowUpState, но до fallback;
  6) faq — статические экраны + FSM поиска;
  7) objections — статические экраны + стоп-лист;
  8) selection / search / build / voice — прочие сценарии;
  9) fallback — последним: любой нераспознанный текст → AI.

main(): init_db() (движок+таблицы+сид, идемпотентно) → get_ai_provider()
(fail-fast при неверном AI_PROVIDER) → фоновые задачи reminders_loop и
upcoming_loop → бесконечный polling с авто-рестартом (backoff 5→60 сек);
finally: отмена фоновых задач + close_db().

5. КОНФИГУРАЦИЯ И ЛОГИРОВАНИЕ
-----------------------------

Без BOT_TOKEN — SystemExit. Bot создаётся один (с AiohttpSession(proxy), если

dialog (JSON-события действий пользователя: menu_open, scenarios_open,
cheatsheet_open {user_id, name, ...} — удобно разбирать аналитикой).

6. РОУТЕРЫ handlers/ (по модулям)
---------------------------------
early_buttons.py   «Ранние кнопки меню». Роутер с двумя message-хендлерами,
                   регистрирующими РЕАЛЬНЫЕ реализации из других модулей:
                   menu.button_ai_assistant («🤖 AI-ассистент») и
                   cheatsheets.button_cheatsheets («📚 Шпаргалки»). Обе с
                   state.clear() внутри → раздел открывается из любого
                   сценария. Легаси-имя ai_button.py удалено; menu/cheatsheets
                   сохраняют собственные регистрации как failsafe.

calculator.py      «💰 Калькулятор», «📊 История расчётов», /cancel.
                   FSM MarginState: choosing_model → waiting_for_cost →
                   waiting_for_delivery → …; расчёт по прайсу из БД (Price),
                   объёмные скидки, запись в calc_history.
                   РЕШЕНО (17.09.2026): «можно смело торговаться» — только при
                   безопасной скидке ≥ 2 500 ₽ (SMART_TRADE_MIN); условие по
                   ступени «НДС 5%» убрано по решению владельца.

menu.py            /start (main_kb), /help, /ai, /checklist, стоп-лист, памятка,
                   обратная связь (FSM FeedbackState → админу), оценка AI
                   (fb_good/fb_bad), легаси-цепочка ТТХ: row:<ряд> →
                   model:<код> (карточка с фото); ttx_rows_kb/callback_row
                   переиспользуются «Шпаргалками».

cheatsheets.py     «📚 Шпаргалки» — inline-меню справочных разделов
                   (CHEATSHEET_TEXT, _cheat_kb): Каталог моделей (cheat:ttx),
                   Подбор (cheat:selection), Сценарии (cheat:scenarios),
                   FAQ (cheat:faq), Возражения (cheat:objections),
                   Стоп-лист (cheat:stoplist), Памятка (cheat:memo).
                   Экраны разделов рендерятся функциями соответствующих
                   роутеров; лог cheatsheet_open.

scenarios.py       «🎯 Сценарии»: список (scn:list / кнопка меню), карточка
                   сценария (scn:<id>), «Всё одним сообщением» (scn:full);
                   «📦 Карточка модели» внутри сценария отдаётся menu (model:).

followup.py        «⏰ Напоминания»: CRUD дел (fup:*), FSM FollowUpState
                   (waiting_for_text), хранение в follow_ups.
                   reminders_loop — утренняя сводка в DAILY_SEND_HOUR:00
                   (🔴 просроченные + 🟡 на сегодня), защита от дублей ключом
                   last_daily в settings. upcoming_loop — напоминания
                   «за 10/5/2 минуты» до событий с due_at, журнал
                   followup_reminders.

faq.py             «❓ FAQ»: категории из БД (faq_categories/faq_questions),
                   экраны категория → вопрос → ответ, поиск (faq:search → FSM
                   FaqState.waiting_for_query), scoring-поиск по словам,
                   «меню-зеркало» faq:menu, отмены, невалидные callback → alert.

objections.py      «💬 Возражения»: список (obj:list), карточки (obj:<id>),
                   «🛑 Только стоп-лист» (obj:stop), «Всё одним» (obj:full).

selection.py       «🧠 Подбор» (экспресс-подбор АКБ): FSM SelectionState,
                   шаги sel:a (тип АКБ 6S/8S/не знаю) → sel:b (разъём) →
                   sel:c (ёмкость) → sel:drone → sel:frame; sel:restart —
                   заново с шага А; в конце — подходящие модели.

search.py          «🔎 Поиск»: мульти-фильтр по каталогу (srch:* — выбор
                   фильтров, srchm:* — множественный выбор значений),
                   результаты — карточки моделей.

build.py           «🔧 Своя сборка»: FSM BuildState (waiting_for_config →
                   waiting_for_connector), build_conn:* — выбор разъёма.

voice.py           Голосовые сообщения: voice → AI-прокси (распознавание) →
                   текст обрабатывается как вопрос.

fallback.py        Последний роутер: текст не из кнопок → AI (handle_ai_request
                   из ai/ai.py); неизвестные /команды — молча; прочий контент —
                   подсказка «понимаю текст и голосовые».

7. FSM-СОСТОЯНИЯ
----------------
states/states.py (общие): FeedbackState (обратная связь), BuildState
(конфигурация, разъём), SelectionState (step_a…step_frame).
Локальные в роутерах: MarginState (calculator.py: выбор модели → закупочная
цена → доставка → …), FaqState (faq.py: ввод поискового запроса),
FollowUpState (followup.py: текст напоминания).
Паттерн «ранних кнопок»: меню-кнопки зарегистрированы РАНЬШЕ сценариев и
сами сбрасывают state — сценарий не может «съесть» нажатие.

8. НАВИГАЦИЯ «ШПАРГАЛОК» (фикс 17.09.2026)
------------------------------------------
Меню разделов = CHEATSHEET_TEXT + 7 кнопок. Входы: reply «📚 Шпаргалки»
(early_buttons — из любого сценария) и cheat:menu с экранов разделов.

Схема возвратов — каждый экран раздела заканчивается «⬅️ В шпаргалки»
(cheat:menu), из меню разделов «⬅️ В меню» (cheat:back) ведёт в главное меню:
  • Каталог моделей (cheat:ttx / легаси «📊 ТТХ»): «⬅️ В шпаргалки»;
    список моделей ряда → «⬅️ К рядам» (cheat:ttx);
  • Подбор, шаг А (sel:a / легаси «🧠 Подбор»): «⬅️ В шпаргалки»;
    шаги глубже → sel:restart на шаг А;
  • Сценарии: «⬅️ В шпаргалки» (после «Всё одним сообщением»);
  • FAQ: «⬅️ В шпаргалки» в одном ряду с «❌ Закрыть»;
  • Возражения: «⬅️ В шпаргалки» (после «стоп-лист / всё одним»);
  • Стоп-лист и памятка (статические тексты): «⬅️ В шпаргалки» (_back_kb) —
    раньше они сразу выпадали в главное меню, минуя меню разделов.

Технически: cheat:menu и статические экраны показываются через
utils.ui.edit_or_send — edit_text, а при невозможности правки новое
сообщение (карточки моделей содержат фото, там edit_text падает);
в конце callback.answer(). Свои регистрации в menu/cheatsheets оставлены
как failsafe на случай съедания кнопки будущими сценариями.

13. СИСТЕМА НАПОМИНАНИЙ (follow-up)
-----------------------------------
followup.py, запускается из bot.main() после init_db():
  reminders_loop(bot) — скан follow_ups; в DAILY_SEND_HOUR:00 утренняя сводка:
                        🔴 просроченные + 🟡 на сегодня; повтор в тот же день
                        блокируется ключом last_daily в таблице settings;
  upcoming_loop(bot)  — предварительные напоминания «за 10/5/2 минуты» до дел
                        с точным due_at; каждая отправка фиксируется в журнале
                        followup_reminders (защита от дублей);
  finally в main(): задачи cancel() + close_db().
