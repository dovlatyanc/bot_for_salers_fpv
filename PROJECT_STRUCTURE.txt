1. НАЗНАЧЕНИЕ И СТЕК
--------------------
Telegram-бот для продавцов FPV-дронов и комплектующих. Умения:
  • 💰 Калькулятор маржи — FSM-расчёт по прайсу, скидки/объёмы, история расчётов;
  • Каталог АКБ — ряды 6S/8S, карточки моделей с фото (вход: «📊 ТТХ»-цепочка
    и раздел «Каталог моделей» в «📚 Шпаргалках»);
  • 🧠 Подбор — экспресс-подбор АКБ (дрон → разъём → ёмкость);
  • 🔎 Поиск — мульти-фильтр по каталогу;
  • 🔧 Своя сборка — FSM «конфигурация или параметры (12В, мА·ч, А) → разъём»;
  • 🎯 Сценарии продаж, 💬 Возражения, ❓ FAQ (категории + поиск), стоп-лист,
    памятка, /checklist;
  • ⏰ Напоминания (follow-up) — CRUD личных дел, утренняя сводка в 9:00,
    предварительные напоминания «за 10/5/2 минуты»;
  • 🤖 AI-ассистент — fallback на любой текст, голосовые (распознавание),
    оценка ответов 👍/👎, обратная связь админу.

Стек: Python 3.14 · aiogram 3.13+ (FSM — кастомный SQLAlchemyStorage в БД,
переживает рестарт) · SQLAlchemy 2 async +
aiosqlite (SQLite data/bot.db; переход на PostgreSQL = DB_URL в .env) ·
python-dotenv · aiohttp. AI: Cloudflare AI Worker или YandexGPT+SpeechKit —
выбор через AI_PROVIDER в .env. fpv-ai-proxy — отдельный Node-проект
(Cloudflare Worker) для проксирования AI и раздачи фото моделей.

Запуск:  .venv\Scripts\python.exe bot.py   (из корня; в .env нужен BOT_TOKEN)
Тесты:   .venv\Scripts\python.exe -m pytest -q   → 511 passed / 0 failed
Проверки: .venv\Scripts\python.exe -X utf8 _verify_<имя>.py

3. СЛОИ И НАПРАВЛЕНИЕ ЗАВИСИМОСТЕЙ
----------------------------------
config ← data/states/keyboards/utils/ai/services ← handlers ← bot.py

Зависимости строго в одну сторону, циклов нет:
  • каждый модуль берёт общие ресурсы (bot, логгеры, env) только из config;
  • каждый роутер объявляет свой Router и НЕ импортирует bot.py;
  • хендлеры переиспользуют show-функции и тексты друг друга (например,
    cheatsheets рендерит экраны через функции scenarios/faq/objections/selection).

4. ТОЧКА ВХОДА bot.py — ПОРЯДОК РОУТЕРОВ И ЗАПУСК
-------------------------------------------------
Порядок include_router КРИТИЧЕН (aiogram отдаёт апдейт первому подходящему;
контракт — tests/test_verify_all.py):
  0) admin — админ-команды и шаги админ-FSM раньше FSM-сценариев и fallback
     (калькулятор ловит любой текст в своих состояниях);
  1) early_buttons — «ранние» кнопки «🤖 AI-ассистент» и «📚 Шпаргалки»:
     открываются из любого FSM-сценария (нажатие сбрасывает сценарий и открывает
     раздел; раньше кнопку «съедал» активный сценарий — «выход в меню»);
  2) calculator — FSM-ввод не должен перехватываться fallback'ом AI;
  3) menu — /start, callback model:<код> из сценариев обрабатывается здесь;
  4) cheatsheets — «📚 Шпаргалки» (cheat:*) сразу после menu;
  5) scenarios — после menu: кнопки «📦 Карточка <модель>» перехватывает menu;
  6) followup — FSM ограничен FollowUpState, но до fallback;
  7) faq — статические экраны + FSM поиска;
  8) objections — статические экраны + стоп-лист;
  9) selection / search / build / builder / voice — прочие сценарии
     (builder — сразу после build и до voice: FSM-ввод part_input
     конструктора не должен уходить в fallback AI);
  10) fallback — последним: /health (статус AI, только админ), затем любой
      нераспознанный текст → AI.

main(): init_db() (движок+таблицы+сид, идемпотентно) → get_ai_provider()
(fail-fast при неверном AI_PROVIDER) → фоновые задачи reminders_loop,
upcoming_loop, heartbeat (пульс для watchdog, deploy/watchdog.py) →
бесконечный polling с авто-рестартом (backoff 5→60 сек);
finally: отмена фоновых задач + close_db(). Сбои AI в рантайме фатальны
только на старте с неверным конфигом: дальше обёртка resilience (раздел 12).

6а. «🛠 КОНСТРУКТОР ДРОНОВ» (ЭТАПЫ 1–10)
--------------------------------------

BUILD_SLOTS (все обязательные: frame, motor, prop, fc_esc_stack, vtx, camera,

(карточка печатает «➖ Рама: под заказ (нет на складе)»); рама 6/8-моторных
сборок — статус «под заказ» БЕЗ дюймовой привязки: в свободном режиме после
выбора размера с 6-моторными серийными сборками бот спрашивает число моторов
(b:motors:4/6), при 6/8 моторах слот frame показывает экран «Рамы … на складе

8. НАВИГАЦИЯ «ШПАРГАЛОК» (фикс 17.09.2026)
------------------------------------------
Меню разделов = CHEATSHEET_TEXT + 7 кнопок. Входы: reply «📚 Шпаргалки»
(early_buttons — из любого сценария) и cheat:menu с экранов разделов.

Схема возвратов — каждый экран раздела заканчивается «⬅️ В шпаргалки»
(cheat:menu), из меню разделов «⬅️ В меню» (cheat:back) ведёт в главное меню:
  • Каталог моделей (cheat:ttx / легаси «📊 ТТХ»): «⬅️ В шпаргалки»;
    список моделей ряда → «⬅️ К рядам» (cheat:ttx);
  • Подбор, шаг А (sel:a / легаси «🧠 Подбор»): «⬅️ В шпаргалки»;
    шаги глубже → sel:restart на шаг А;
  • Сценарии: «⬅️ В шпаргалки» (после «Всё одним сообщением»);
  • FAQ: «⬅️ В шпаргалки» в одном ряду с «❌ Закрыть»;
  • Возражения: «⬅️ В шпаргалки» (после «стоп-лист / всё одним»);
  • Стоп-лист и памятка (статические тексты): «⬅️ В шпаргалки» (_back_kb) —
    раньше они сразу выпадали в главное меню, минуя меню разделов.

Технически: cheat:menu и статические экраны показываются через
utils.ui.edit_or_send — edit_text, а при невозможности правки новое
сообщение (карточки моделей содержат фото, там edit_text падает);
в конце callback.answer(). Свои регистрации в menu/cheatsheets оставлены
как failsafe на случай съедания кнопки будущими сценариями.
